# Конкретные развилки исследования

Вместо общего «исследовать осуществимость» агент связывает вопрос, решение,
метод получения данных и проверяемые условия альтернатив. Расширены существующие
research_selection_reviews/gaps/answer_branches, новых копий состояния нет.

Новые записи schema_version=2. Каждая значимая развилка имеет минимум две
альтернативы и отдельный исход insufficient_data с целевым next_step. Формат v1
остаётся читаемым, валидным и сохраняется как история; автоматическое
сопоставление для него не заявляется. prepare создаёт v2, запись остаётся через
обычный research_selection.py record с проверкой версий, журнала и источников.

## Пример ресурсного вопроса

| Условие из отдельной проверки | Последствие | Следующий шаг |
|---|---|---|
| O1 feasible: полный минимальный план укладывается в записанные условия | Условно сохранять прототип | Показать допущения владельцу до кода |
| O1 infeasible И O2 feasible | Предложить отдельно проверенную бумагу | Передать выбор владельцу |
| Оценка, ёмкость, альтернативный ресурс или календарные зависимости неизвестны | Не назначать победителя по этой развилке | Получить конкретную оценку/доступные часы или предложить ограниченную разрешённую проверку |

condition.kind=feasibility ссылается на option_id/outcome в requirements.
Исходы вычисляются существующей проверкой осуществимости; текущие ресурсы
не копируются в развилку. AND-условие не выполнено, если хотя бы одна часть
опровергнута; если опровержения нет, но часть неизвестна, исход неизвестен.
Запись not_recorded/stale/blocked или другой контекст проверки не доказывают
осуществимость. Оценочные часы и календарный план показываются как допущения.
Ненадёжная декомпозиция или недоступный способ проверки требуют уточнения:
пока access/adequacy метода не подтверждены, по его условиям нельзя выбрать ветку.
Человеко-часы не сравниваются с днями, последовательность проверяется отдельно.

## Другие наблюдения и пороги

Для condition.kind=observation агент после чтения источника записывает indicator,
criterion, method_id, assessment, rationale и evidence_ids. met и not_met требуют
фактических оснований. Unknown не подменяется ложностью. Скрипт проверяет
происхождение, противоречия и типы; смысл прочитанного оценивают агент и человек.

Числовые критерии вынесены в thresholds с единицами, основанием и ссылками.
Поддерживаются owner_agreed, empirical и derived. Для согласования нужна ссылка
на фактический ответ и owner_input, для эмпирики — measured_fact с
project_observation. Выведение требует объяснения из фактов. Предложенный порог
не считается правилом допуска. Синтетический live-результат и гипотеза не закрывают
условие. Авторский пример явно помечен и не подтверждает реальные ресурсы.

Инструмент не вычисляет произвольную формулу по тексту и не исполняет выражения
из источника. Он не может проверить, действительно ли цитата обосновывает весь
смысл критерия, или что все числовые правила честно вынесены из прозы: это
содержательная проверка по workflow. Детектор чисел — дополнительная защита,
не доказательство полноты. Не называть запись независимым подтверждением.

## Результат и новые данные

branch_resolutions показывает выбранную условную ветку, проверенные состояния,
ID ресурсной версии, причину и следующий шаг. Для matched нужно ровно одно
выполненное условие и отсутствие неизвестных конкурирующих условий. Пересечение,
недостающие сведения и отсутствие подходящего условия ведут в insufficient_data
с пустыми option_ids. Нерешённую значимую развилку нельзя закрыть как answered.

Новые данные сначала делают старое сравнение stale. После явного пересмотра
источников и проверки осуществимости сохраняется следующая версия исследования.
История не удаляется; открытие ничего не записывает. Сопоставление не меняет
рекомендованный/выбранный вариант, next_action, сроки или обязательства и не
запускает исследование. Ветка PAPER — предложение, а не согласие владельца.

## Проверка

```text
python scripts/research_selection.py report examples/research-branches-case/project.json
python scripts/verify_branch_demo.py
python -m unittest discover -s tests -v
```

Временная копия проходит UNKNOWN → PROTOTYPE → PAPER после двух изменений
авторского источника. Проверяются stale, версии, явное обновление оснований,
вызов проверки осуществимости, причина развилки и сохранение выбора человека.
Ресурсный дефицит текущего рекомендованного O1 продолжает блокировать ready,
пока человек не примет решение. Это тест контракта, не LLM benchmark и не
измерение спроса, экономии или превосходства решений.
