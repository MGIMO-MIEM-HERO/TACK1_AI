# Маршрутизация моделей и инструментов

Принцип: самый дешёвый исполнитель, который даёт нужное качество, и детерминированный код везде, где нужен расчёт. Число агентов — не цель: отдельный субагент оправдан, только если даёт изоляцию контекста или заметную экономию.

| Задача | Исполнитель | Почему |
|---|---|---|
| Расчёты, интервалы, воронки, проверка ссылок | скрипты `scripts/*.py` | воспроизводимо, 0 токенов, нет галлюцинаций чисел |
| Чтение и извлечение фактов из многих страниц | субагент `source-researcher` (модель `sonnet`) | дешевле в 2 раза; сырые страницы не попадают в основной контекст (защита от инъекций, экономия) |
| Рамка, синтез, варианты, стратегия | основная модель сессии (`opus` или эквивалент) | ошибки здесь дороже всего |
| Критика вариантов и записки | субагент `devils-advocate` (модель `opus`) | нужен независимый контекст и сильное рассуждение; один проход на версию |
| Модельные респонденты | основная модель или отдельный чат; для черновых наборов — `haiku` | синтетика — дешёвый этап; качество ограничено природой метода |
| Классификация/разметка большого числа коротких текстов | `haiku` | простая задача, большой объём |

Цены для оценки — `config/model_prices.json` (USD за 1 млн токенов, list-цены, дата проверки внутри файла). В Cursor/Codex имена моделей другие: записывайте в журнал фактическое имя. Если цены нет в таблице, стоимость = неизвестна.

## Экономичность

- Сначала `checkpoint.py resume` и `ledger.py status`. Не перечитывать то, что уже записано в `project.json`.
- Читать только файлы, нужные текущему шагу. Большие таблицы обрабатывать скриптом, а не загружать в контекст.
- Один проход критика на версию решения, а не на каждое изменение.
- `ledger.py begin` перед дорогим действием: если оно уже сделано, скрипт вернёт код 3 — не повторять.
