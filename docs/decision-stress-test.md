# Проверка решения на прочность

Агент показывает исходную рекомендацию, ключевые допущения и сравнение всех
вариантов при неблагоприятных условиях. Возможны сохранение выбора, условная
смена рекомендации и честный вывод «данных недостаточно». Инструкция LLM:
[`workflows/decision-stress-test.md`](../workflows/decision-stress-test.md).

## Запуск

```sh
python scripts/stress_test.py prepare projects/my-case/project.json --review-id R1 --out projects/my-case/stress-R1.json
# Агент содержательно заполняет JSON после чтения необходимых материалов.
python scripts/stress_test.py record projects/my-case/project.json --review projects/my-case/stress-R1.json
python scripts/stress_test.py inspect projects/my-case/project.json
python scripts/stress_test.py report projects/my-case/project.json --out projects/my-case/stress-R1.md
```

`prepare` работает и до появления рекомендации: в базовой версии сохраняется
явное `recommended_option_id: null`, а карта, записка и inspect поясняют, что
сравнение с базовой рекомендацией невозможно. Можно записать
`insufficient_evidence` либо обоснованный `conditional_option` — условный вариант
с действующими фактическими основаниями, без создания рекомендации проекта.
`keep`/`switch` требуют существующей базовой рекомендации. При её наличии
обоснование рекомендации по-прежнему обязательно.

Шаблон содержит пропуски, которые
не пройдут `record`: это защита от механического заполнения. Исходные материалы
и состояние нельзя заменить экспортом. Для повторного экспорта укажите новое имя.
Все команды, кроме `record`, читают состояние без записи; `record` добавляет
версию в `decision_stress_tests`, фактическую UTC-дату записи и запись журнала.
Схема: `schemas/project.schema.json#/$defs/decisionStressReview`; перекрёстные правила проверяются
стандартным `validate_project.py` без сторонних библиотек.

## Связь с состоянием

Базовая версия содержит project_id, исходную рекомендацию, пространство ID,
снимок ограничений и хеш значимого состояния с содержимым локальных источников.
Служебные даты, checkpoints и самопроверка не создают ложного устаревания;
запись стресс-разбора не инвалидирует собственную базу. Она меняет полный
контент проекта, поэтому содержательную самопроверку стратегии нужно обновить.
В истории сохраняются прежние версии, включая ссылки на прежние объекты.

При изменении ограничений или оснований последняя версия становится `stale`.
Показываются изменившиеся ограничения/источники и зависимости для пересмотра.
Для ограничений старого формата без отдельных ID список консервативный:
включаются все связи записанных допущений, а не утверждается точная причинность.
Для источников и выводов используется существующий транзитивный обход
`checkpoint.impacted`. `start.py`, `checkpoint.py resume`, аудит и записка
показывают состояние разбора. Устаревший/заблокированный разбор запрещает
`report --final`; черновик явно сохраняет предупреждение.

Ни один сценарий не меняет рекомендацию, решение владельца или обязательства
автоматически. Новая фактическая рекомендация — отдельное содержательное действие
агента с объяснением и пересмотром обеих стратегий, а выбор остаётся человеку.

## Проверяемая демонстрация

```sh
python scripts/start.py examples/decision-stress-case/project.json --json
python scripts/stress_test.py inspect examples/decision-stress-case/project.json
python scripts/verify_stress_demo.py
```

Авторский пример, не официальный бриф: O1 — локальный прототип, O2 — бумажная
проверка, O0 — оставить как есть, O3 — заморозить. Три сценария:

- разработчик недоступен → условно O2 вместо O1 по условию E1;
- интеграция задержана, но локальная проверка от неё не зависит → сохранить O1
  по E2, при этом осуществимость срока всё ещё нужно подтвердить;
- условие E1 опровергнуто, замены нет → недостаточно данных, победитель не выбран.

`verify_stress_demo.py` работает во временной копии. Меняет одно ресурсное
ограничение, проверяет stale и блокировку итогового экспорта, затем воспроизводит
ЯВНО подготовленный пересмотр O1 → O2 с согласованными формулировками стратегий,
добавляет R2 и проверяет сохранение R1. Человек по-прежнему ничего не выбирал.
Проверка не вызывает модель или сеть и не измеряет качество реального LLM.

## Ограничения

Это условное рассуждение, а не прогноз вероятности, симулятор бизнеса или
независимая экспертиза. Проверки обеспечивают полноту записей, происхождение
оснований, допустимые ссылки и актуальность; смысловую достаточность сравнения
оценивает LLM и человек. Реальный эффект, стоимость и превосходство над обычным
чатом этим примером не доказаны. История не является защищённым от автора аудитом.
При недоступном источнике сохранение разбора не обходит его проверку.

Запись состояния атомарна; журнал дописывается отдельно. Если журнал не удалось
дописать после сохранения, команда явно сообщает о частичном успехе. Сначала
прочитайте проект, не повторяйте действие с новым ID вслепую. Никаких фоновых
процессов, платных сервисов и дополнительных зависимостей не требуется.
