# Основной учебный кейс: формальный пересмотр O1 → условный O2

Это продолжение paired-test из прогона 1, а не подмена основного кейса отдельной
демонстрацией паспорта. Исторический прогон и исходные файлы оставлены неизменными.
В baseline/ сохранены его project.json и журнал до продолжения, inputs/ содержит
те же пять переданных учебных файлов. Ресурсы, результаты и прежний выбор — условия
авторского кейса, а не реальные наблюдения или согласия участников команды.

Добавлены текущие формальные записи:

- Осуществимость: O1 неосуществим для указанного горизонта из-за явно недоступного
  разработчика и отсутствующего готового прототипа. Для O2 разрешение есть,
  но исполнитель, часы и полнота материалов неизвестны. O2 имеет unknown,
  а не feasible. Даты начала, оценки часов и новые люди не выдуманы.
- Исследования: проверяемая развилка Q1 возвращает UNKNOWN, поскольку бумажный
  план не проверен отдельно по ресурсам. Для Q2 неизвестна комплектность;
  CSV со значением 3 не заменяет тексты сценариев. Для Q3 отсутствие замеров
  ведёт к осторожной формулировке, не к обещанию ускорения.
- Сценарии: отдельно проверены гипотетические риски отсутствия исполнителя
  бумаги и неполноты материалов. Это условные рассуждения, не новые наблюдения.
- Обещания: M1 не подтверждено, но не опровергнуто; CAP1 остаётся planned.
  Принята осторожная формулировка, реальных измерений или экспериментов нет.

Выбор O1, обязательства, сроки, результаты и прежние рассмотрения сохранены.
Новые ответы владельца не записаны. Аудит ready остаётся отрицательным из-за
прежнего выбора O1: финальное решение нельзя объявить согласованным.

Обычный черновой экспорт теперь создаёт записку «ДЛЯ ПЕРЕСМОТРА — НЕ ГОТОВ К
ИСПОЛНЕНИЮ» и автоматическую карту с видимыми блокерами. Финальный экспорт
блокируется. Недоступные/изменившиеся источники, поиск вместо первоисточника,
неактуальные основания новой рекомендации и повреждённый журнал по-прежнему
не разрешают даже такой черновой экспорт.

```text
python scripts/project_tool.py report examples/paired-case-review/project.json --out /путь/к/новой/decision-brief.md
python scripts/start.py examples/paired-case-review/project.json --passport
python scripts/verify_case_review_demo.py
```

Последняя команда восстанавливает исходный кейс в временной папке, записывает
четыре проверки, проверяет их актуальность, сохранение O1/обязательств/результатов,
отказ финального экспорта и появление записки с картой. На карте проверяется
наличие всех четырёх разборов, паспорта и различение рекомендации O2 и выбора O1.
Это проверка файлового агента, не LLM benchmark, спрос или независимая экспертиза.
