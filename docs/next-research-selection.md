# Выбор следующего исследования

Агент развивает имеющийся план: сравнивает пробелы по способности изменить
решение, предлагает доступный достаточный способ проверки и объясняет, когда
сбор данных для текущего выбора можно закончить. Никаких выдуманных вероятностей,
точных рейтингов или денежных оценок «ценности информации».

## Использование

В существующем `research_questions` нужны стабильные question_id, question,
could_change. Старые проекты читаются без миграции, пока новая функция не
запрашивается. Инструкция LLM: [workflow](../workflows/next-research-selection.md).

```sh
python scripts/research_selection.py prepare projects/my-case/project.json --review-id R1 --out projects/my-case/research-R1.json
# Агент читает материалы и заполняет сравнение, а не просто ставит флаги.
python scripts/research_selection.py record projects/my-case/project.json --review projects/my-case/research-R1.json
python scripts/research_selection.py inspect projects/my-case/project.json
python scripts/research_selection.py report projects/my-case/project.json --out projects/my-case/research-R1.md
```

Шаблон намеренно не проходит record до содержательного заполнения. Схема
`schemas/project.schema.json#/$defs/researchSelectionReview`; дополнительные
проверки выполняются стандартным `validate_project.py`, без новых зависимостей.

## Содержание сравнения

Каждый gap ссылается на реальный вопрос, варианты и evidence. Если формальных
вариантов ещё нет, связь задаётся через описание решения, а не выдуманные ID.
Две ветки ответа показывают разные последствия; вопросы контекста можно отложить.
Приоритеты качественные: critical, high, defer, undetermined. Скрипт не присваивает
баллы и не объявляет один метод объективно самым дешёвым.

Методы имеют доступность и достаточность, объяснение и источники. Время и ресурсы
сохраняются отдельно как unknown/estimated/observed: неизвестное — null, оценка
имеет значение с единицами и основанием, наблюдение — фактическую ссылку.
Самый доступный способ бесполезен, если не отвечает на вопрос решения.

Следующее действие:

- investigate — открытый значимый вопрос и выбранный доступный достаточный метод;
- clarify — неопределённость приоритета/доступа/достаточности явно названа;
- stop — фактов достаточно ДЛЯ ТЕКУЩЕЙ ГРАНИЦЫ решения, дальнейший сбор не различит
  варианты; оставшиеся ограничения продолжают отображаться.

Открытый критический барьер нельзя заменить второстепенным исследованием.
Закрытый вопрос не предлагается повторно. Не допускается stop при нерешённых
critical/high/undetermined вопросах, меняющих решение, или на одних гипотезах.
Контекстный вопрос не выдаётся за выбранное исследование, различающее варианты.

## История, продолжение и совместимость

`research_selection_reviews` дополняется версиями. Общий с двумя предыдущими
функциями механизм проверяет сохранённые источники, отозванные основания, хеш
контекста, целостность журнала и конкурентное изменение состояния перед записью.
Файл состояния записывается атомарно; журнал дописывается отдельно. При сбое
после сохранения CLI явно сообщает о частичном успехе: прочитайте проект перед
повтором, не создавайте следующую версию вслепую.

Новые вопросы/ответы, ограничения, evidence, источники или стратегия делают
старое сравнение stale. Приоритеты нужно сравнить заново; хеш не заменяет анализ.
Сами записи трёх видов обзора не инвалидируют друг друга, а общая самопроверка
стратегии после новой записи требует обновления. Результат виден в start/resume,
аудите и записке. Устаревшее/заблокированное сравнение запрещает итоговый экспорт.

Инструмент не проводит интервью, не ищет в сети и не меняет next_action,
рекомендацию, выбранный человеком вариант или обязательства. Выбранный шаг
выполняет LLM через доступные инструменты среды. План не становится наблюдением.

## Демонстрация

Новый формат v2 использует существующие answer_branches, а не отдельный реестр
решений. Подробности и пример — [конкретные развилки](research-decision-branches.md).
Старые v1 и их история не переписываются; новые шаблоны по умолчанию — v2.

```sh
python scripts/start.py examples/next-research-case/project.json --json
python scripts/verify_research_demo.py
```

Авторский учебный случай, не бриф МегаФона: прежде чем исследовать другие
аспекты, агент предлагает прочитать доступное техническое условие. После чтения
POLICY появляется E2, Q1 закрывается и приоритет переходит к достаточности шаблона
Q2. После чтения FORM появляется E3, агент явно предлагает бумажный способ и
объясняет остановку исследования только для выбора подготовки сценария.

Проверка работает во временной копии, сохраняет R1/R2/R3 и проверяет stale,
блокировку экспорта и пересмотр. Исходники не меняются, людей не опрашивают,
выбор владельца не записывают, UX/спрос/экономический эффект не объявляют
проверенными. Это проверка механики на подготовленном сценарии, не LLM benchmark.

## Ограничения

Методы, их достаточность, охват вопросов и объяснение остановки оценивают LLM
и человек. Формальные проверки не доказывают глобальную оптимальность выбора,
истинность текста или достоверность произвольной оценки времени. Достаточность
сохраняет конкретную рамку решения; новая цель требует нового разбора.
Неизвестные затраты не означают бесплатность. Новых сервисов и зависимостей нет.
