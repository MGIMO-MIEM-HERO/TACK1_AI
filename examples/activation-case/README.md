# Демо-кейс: ясное сообщение при активации

## Контекст

Вымышленная цифровая услуга хочет понять, помогает ли объясняющая ценность сервиса карточка в приветственном сценарии увеличить первую активацию. Это демонстрационный вопрос, не официальный бриф МегаФона. Названия, пользователи и записи придуманы для проверки воспроизводимого процесса.

## Файлы

- `project.json` — рамка, источники и варианты.
- `inputs/users.csv` — одна строка на синтетического пользователя и случайно назначенный вариант сообщения A/B.
- `inputs/outcomes.csv` — одна строка на пользователя с метриками активации/возврата/защитными исходами.
- `inputs/events.csv` — событие на строку для продуктового пути.
- `inputs/support.csv` — ноль или одно синтетическое обращение на пользователя в этой версии.
- `outputs/analysis.json` и `outputs/analysis.md` — детерминированный анализ.

## Воспроизведение

Из корня проекта:

```bash
python3 scripts/generate_demo.py
python3 scripts/analyze_experiment.py
python3 scripts/validate_project.py examples/activation-case/project.json
```

Скрипт генерации фиксирует seed; можно пересоздать CSV. Анализатор сводит события/обращения к уникальному пользователю до сравнений, считает Wilson-интервалы долей и Newcombe-интервал разницы долей. Сегменты обозначены как поисковые. Скрипт не выдаёт p-values или причинные выводы.

## Вопросы для агента

1. Что является главным результатом, а что ближайшей измеримой метрикой изменения?
2. Какие точки выпадения видны в пути, и соответствует ли знаменатель каждой конверсии?
3. Что показывает назначение A/B для активации и защитных метрик? Что можно заключить, а что нельзя?
4. Есть ли разница по устройствам/каналам, которую стоит изучить дальше? Не называй её причиной.
5. Какой тест или исследование должно предшествовать запуску?
6. Сравни минимум три варианта и зафиксируй, какое новое свидетельство изменило бы рекомендацию.

## Продолжение после перерыва

В новом чате запустите `python3 scripts/checkpoint.py examples/activation-case/project.json resume`. Агент увидит этап сравнения вариантов и следующий шаг. Для проверки пересмотра работайте с копией проекта и замените один локальный источник. Контрольная точка покажет его ID и связанные выводы.

## Ограничения

Симуляция задаёт известные искусственные вероятности; это не оценка реального спроса. Метрики созданы именно для демонстрации работы инструментов. Компьютерный порог в JSON — только демонстрационный фильтр для передачи человеку, не автоматическое решение о запуске. Конкурсную демонстрацию нужно адаптировать к официальному брифу и разрешённым открытым источникам.
