# Пересмотр по существенности

Используйте прежние источники, evidence, варианты, контрольные точки и журнал.
Отдельного реестра событий нет. Просмотр ничего не записывает.

1. `python scripts/material_changes.py inspect <project.json>` показывает режим,
   изменения, цепочку зависимых оснований и вариантов, историю и версию.
   Для старого проекта режим включается отдельной командой
   `python scripts/material_changes.py enable <project.json>`.
   Сначала разберите незавершённые изменения старых источников. Включение меняет
   правила отпечатков: прежние проверки требуют обновления, подтверждения остаются
   историческими. Автоматического переноса согласия нет.
2. Автоматически косметическими считаются только отображаемые названия проекта
   и источника, пробелы и порядок ключей корректного JSON при прежних значениях.
   Порядок массивов, написание чисел, даты, авторство, статус, область применимости
   и метод не игнорируются. Повторные ключи и некорректный JSON сравниваются по байтам.
3. Чисто косметическое событие сохраните обычным `checkpoint.py <project.json>
   save --summary "Что оформлено"`. Оно остаётся в истории без нового согласования.
4. Для остальных изменений: `python scripts/material_changes.py prepare
   <project.json> --out <новый-review.json>`. Прочитайте источник и проверьте
   затронутые основания, осуществимость и исследовательские развилки. Скрипт
   обнаруживает зависимости, а содержательную оценку делает агент по материалам.
5. Для каждого события заполните `analysis`, `materiality`
   (`cosmetic/material/uncertain`), `decision_effect` (`changed/unchanged/unknown`),
   `evidence_ids`. Укажите `reviewer`, общий `conclusion` и `rationale`.
   «Вывод не изменился» после содержательной правки требует проверяемых фактических
   оснований и объяснения. Гипотеза модели не заменяет факт. Неизвестное влияние
   оставьте unknown; не выдавайте неопределённость за косметику.
6. После проверки и обновления оснований запишите текущее состояние, заново
   подготовьте оценку, если изменился набор событий. Выполните
   `python scripts/material_changes.py record <project.json> --review <review.json>`.
   Устаревшая оценка отвергается. Повтор той же записи сразу после сохранения
   ничего не дописывает. События и оценка хранятся в checkpoint, действие — в журнале.
7. Если вывод изменился или влияние на выбранные основания остаётся неизвестным,
   покажите владельцу один запрос с `question_id` для этой версии. Уведомление,
   самопроверка, просмотр и контрольная точка не являются согласием. Старое
   подтверждение не оживает даже при возврате результата к прежнему значению.
   Уже ожидающий запрос сохраняется при косметическом продолжении.
8. Выполните обычные проверки качества. Оценка «не влияет» не отменяет истёкший
   срок источника, недоступный материал, нарушение происхождения или повреждение
   журнала. `report` показывает последний вывод и объяснение, `inspect` — всю историю.

Не наблюдавшиеся между двумя чтениями изменения не восстанавливаются задним
числом. Все обнаруженные изменения фиксируйте до следующего этапа; чтение само
не создаёт события, запись не является решением владельца.
