# Паспорт решения

## Карточка из текущего состояния

Вызовите `python scripts/start.py <project.json> --passport`. Первой идёт сводка
из четырёх пунктов, затем рекомендация, альтернативы, основания, источники,
неизвестное, осуществимость, условия пересмотра и ответы владельца.
`--passport --json` отдаёт те же данные для среды агента.
Отдельная команда: `python scripts/decision_passport.py <project.json>`.
Для экспорта используйте `--out <новый-файл.md>` или `--json --out <новый-файл.json>`.
Экспорт — снимок для чтения; актуальная карточка каждый раз собирается из project.json.
Карточка не хранит независимую версию решения и не изменяет исходные данные.

Для отклонённого варианта заполните его `selection_assessment`:
`status: rejected`, `reason`, `evidence_ids`. Для ещё открытого — `open`, для
невыбранного — `not_selected`. Не называйте риск или возражение фактом отказа.
Если основания отказа нет, карточка так и сообщает. Рекомендованный вариант
нельзя одновременно пометить отклонённым. Содержательное сравнение делает агент,
структура и ссылки проверяются скриптами; это не доказательство истинности текста.

## Три разных предмета ответа

| Предмет | kind | subject_ref | Что означает |
|---|---|---|---|
| Согласование рекомендации | recommendation | /recommended_option_id | Ответ на рекомендацию и её текущие условия |
| Разрешение действовать | permission | option:O1 | Только заданные минимальные работы и окно из проверки осуществимости |
| Подтверждение данных | data | source:S или evidence:E1 | Только названные исходные данные текущей версии |

Ни один из этих ответов не заменяет остальные. Разрешение не подтверждает ресурс,
согласование рекомендации не запускает работу и не закрывает обязательство.
Исторический chosen_option_id, agreement_reference и ответ по метрике показываются
отдельно, в пределах записанного предмета; из них не выводится согласие с новой рекомендацией.

## Запрос и фиксация фактического ответа

Для новых ответов сначала включите `material-v1` по workflow пересмотра изменений.
Старый проект можно читать без миграции; новые ответы для него не записываются.

1. Получите точные версии: `python scripts/decision_passport.py <project.json>
   --request recommendation --subject /recommended_option_id`. Для других
   предметов используйте таблицу выше. Это запрос, а не подтверждение.
2. Покажите человеку предмет, границы, рекомендацию, альтернативы и существенные
   неизвестные. Не выдавайте условную осуществимость за разрешение действовать.
3. После фактического ответа сохраните отдельный локальный JSON-файл в базе
   проекта. Он содержит только `schema_version`, `project_id`, `kind`,
   `subject_ref`, `decision_version`, `subject_version`, `context` из запроса
   и реальные `confirmation_id`, `outcome` (approved/rejected/needs_changes),
   `statement`, `confirmed_at` с часовым смещением. `confirmed_by` добавляется,
   только если известно, кто ответил. Служебные note/required_reply_fields из
   запроса в ответ не копируются. Не подставляйте время записи вместо неизвестного
   времени ответа: уточните метаданные до фиксации. Общее «да» без ясного предмета
   требует уточнения, а не расширения согласия на все три вида ответа.
4. Файл — входные данные ответа, не новая причина бизнес-рекомендации. Не добавляйте
   его как независимое рыночное доказательство. Сохраните действительный текст
   ответа; агент не должен сам писать положительный ответ от имени владельца.
   Для материалов с персональными/закрытыми данными используйте локальную private/
   и не публикуйте их в Git. Указывайте доступную роль вместо ненужных персональных данных.
5. Выполните `python scripts/decision_passport.py <project.json> --answer <файл>`.
   Скрипт проверит проект, предмет, обе версии, контекст, исходный файл и время.
   Неразобранные изменения нельзя принять записью ответа. Результат дописывается
   в существующий checkpoint (`human_confirmation`) и журнал; chosen_option_id,
   обязательства и сроки автоматически не меняются. Повтор того же ответа — без записи.
6. Сохранённый файл ответа не переписывайте. Для уточнения/отказа — новый ID и файл.
   Последний явный ответ замещает прежний для того же предмета и версии. Исчезновение
   или изменение файла делает ответ непроверяемым, не возвращая прежнее согласие.
   Скрипт проверяет соответствие сохранённой записи файлу, но не удостоверяет личность автора.
   Отпечаток считается по однозначному содержимому JSON: переносы Windows/Linux,
   отступы и порядок полей не меняют ответ. Дублирующиеся поля отвергаются.

## Новые данные

Сначала покажите затронутые основания, затем повторите проверки осуществимости
и развилок. Обновите рекомендацию либо обоснуйте её сохранение. Сохраните оценку
влияния через material_changes. Паспорт и сводка обновятся из того же состояния.
Изменение условий исследования меняет предмет согласования, даже если название
варианта прежнее. Старые ответы не переносятся на новую версию и не оживают при
возврате старого значения. Ответ с неправильной версией отвергается.
Уже рассмотренные старые основания остаются в истории; они не должны блокировать
новую рекомендацию, если не входят в её зависимости.

Проверка полного сценария: `python scripts/verify_passport_demo.py`.
Все ответы в этом сценарии вымышлены и явно помечены authored_example.
Это проверка поведения файлового агента, не испытание ответов модели и не реальные согласования команды.
