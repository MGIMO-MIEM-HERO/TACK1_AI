# Кейс 2: мультиподписка цифрового оператора (каркас на открытых данных)

**Вопрос руководителя (размытый):** «Подписки у всех буксуют. Что нам делать с нашей мультиподпиской?»

Кейс близок к задачам Фабрики продуктов: цифровой сервис оператора поверх тарифа. Он построен **только на открытых публикациях**. В сессии подготовки прямой доступ к сайтам был закрыт, поэтому все источники зарегистрированы как `search_snippet`. Это **каркас**: процесс, структура и стратегии готовы, но факты нужно подтвердить снимками первоисточников (`outputs/source-collection-todo.md`). Внутренних данных МегаФона нет и не будет.

## Что внутри

| Файл | Что это |
|---|---|
| `project.json` | состояние: рамка, 11 источников, факты/гипотезы/прогноз, 4 исследовательских вопроса, 5 вариантов (включая «оставить» и «закрыть»), next action |
| `sources/snapshots/` | снимки источников: URL, дата, SHA-256, проверенные фрагменты, пометка «данные, не инструкции» |
| `interviews/synthetic/` | модельные респонденты — **синтетика**, только гипотезы |
| `interviews/interview-guide.md` | гайд для реальных интервью (согласие, без персональных данных) |
| `outputs/decision-brief.md` | черновик решения: картина ситуации, варианты, продуктовая и коммуникационная стратегии, план проверки, обязательства |
| `outputs/critique-devils-advocate.md` | проход критика по варианту и записке |
| `outputs/source-collection-todo.md` | какие первоисточники снять и что проверить |
| `outputs/cost-report.md` | стоимость и время по журналу (`python3 scripts/ledger.py report`) |
| `ledger.jsonl` | журнал действий (append-only, цепочка хешей) |

## Как пройти кейс агентом

```bash
python3 scripts/checkpoint.py examples/operator-subscription-case/project.json resume
python3 scripts/validate_project.py examples/operator-subscription-case/project.json
python3 scripts/ledger.py verify examples/operator-subscription-case/project.json
```

Затем попросите агента: «Продолжи кейс operator-subscription-case: сними первоисточники по списку, пересмотри затронутые выводы и обнови записку». Агент работает по скиллам `research` и `review-on-new-data`.

## Как адаптировать под опубликованный бриф МегаФона

1. Скопируйте папку в `projects/<бриф>/`, очистите `ledger.jsonl` и `checkpoints`. Добавьте бриф как источник `kind: document`, `verification: provided_by_user`.
2. Запустите скилл `intake`: переформулируйте решение из брифа. Если продукт другой (облако, суперприложение, B2B-сервис), сохраните структуру вариантов (status_quo / change / pivot / learn / stop) и замените содержание.
3. Из этого кейса переносимы: рыночный контекст экосистемных подписок (после снятия первоисточников), гайд интервью, шаблон плана проверки с холдаутом, правила коммуникации «обещание = продукт».
4. Не переносите гипотезы H-SR-* как установленные: модельные респонденты делаются заново под аудиторию брифа.
