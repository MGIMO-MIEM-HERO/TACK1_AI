# Локальная доработка по результатам живых прогонов

Документ описывает доработку, первоначально подготовленную локально. После отдельного разрешения владельца она публикуется через ветку и PR; протокол локальной проверки сохранён как исторический результат до публикации.

## Исправленные неточности

| Проблема | Поведение после доработки |
|---|---|
| Таблица обязательна в любом кейсе | research_requirements явно задаёт необходимые виды источников и причину; отсутствие ненужного вида не блокирует кейс |
| Зелёный структурный аудит принимается за качество | Раздельные structural_ready, content_review и experiment_status; итоговый экспорт требует --final, без него видимый черновик |
| Ссылка/совпадение цитаты считается достаточным доказательством | claim_scope и support с точным локальным фрагментом, ролью и объяснением; качество смысла проверяется workflow, а не объявляется доказанным скриптом |
| Общая методика превращается в спрос/причинность | Нужна подходящая область evidence; синтетика, заметки модели и план не подтверждают реальный эффект |
| 12 вопросов путают с 12 ответами A/B | cases × variants × repeats проверяется против planned_outputs; 12 × 2 × 1 = 24 |
| Порог 3/5 объявляется допуском к разработке | Предложение/согласование/эмпирическое основание разделены; ссылки на основания обязательны, ограничения малой выборки остаются явными |
| План называется проведённым тестом | completed требует локального артефакта результатов и зарегистрированных источников; статус плана отражён отдельно |
| Начало записано после исследования, но время считается измеренным | --retrospective не создаёт длительность; elapsed_s — интервал записей, duration_s требует основания, измеренный ноль сохраняется |
| Два чата на одной версии объявляются улучшением | compare_runs.py проверяет одинаковые артефакты/модель/условия и отказывает версии в статусе улучшения при одинаковой ревизии или несвежем контексте |
| Старые отозванные записи мешают хранить историю | Исторические предупреждения отделены в advisories; использование такого основания выбранным вариантом по-прежнему ошибка |

## Запуск

```text
python -m unittest discover -s tests -v
python scripts/verify_demo.py
python scripts/start.py examples/review-contract-case/project.json --json
python scripts/project_tool.py audit examples/review-contract-case/project.json --ready --quality
```

Новый пример — авторский учебный бриф с явно предложенным планом и
самопроверкой. Пользователей и проведённого эксперимента в нём нет.
Старые кейсы совместимы: структурный аудит по-прежнему доступен; для итогового
экспорта нужно заполнить новый контракт и реально пересмотреть источники.
Старые живые кейсы автоматически не объявляются содержательно проверенными.

## Что не следует заявлять

Улучшения устраняют конкретные ошибки и усиливают контроль процесса.
Автоматическая проверка не доказывает истинность всех текстовых выводов.
Новые поля могут быть заполнены недобросовестно, поэтому сохранены реальные
источники, ограничения и контроль человека. Рост качества/экономия времени
против обычного чата не измерены; сравнение одинаковых продолжений не равно
сравнению версий. Конкурсное видео и дополнительный официальный кейс требуют
отдельной подготовки.
