# Честное сравнение с обычным чатом

Измерение ещё не проведено. Нельзя заявлять выигрыш в скорости, цене или качестве.

Для двух задач (например, удержание и выбор сегмента) используйте одинаковую
модель, исходные материалы, лимит времени и начальный запрос. В первом режиме
обычный чат, во втором — агент с этой папкой. Чередуйте порядок и сохраняйте
все ответы; желательно повторить каждый режим трижды. Отдельно включите
продолжение в новом чате и изменение одного исходного материала.

Фиксируйте:

| Поле | Как считать |
|---|---|
| Полное время | От отправки запроса до проверенного результата, включая исправления |
| Расходы | Модель, поиск и инструменты; неизвестные тарифы обозначать неизвестными |
| Ручная помощь | Минуты и число исправлений пользователя |
| Проверяемость | Доля существенных фактов с корректным источником и координатами |
| Ошибки | Неподтверждённые факты, выдуманные числа, подмена синтетики наблюдениями |
| Стратегия | Разные варианты, возражения, аудитория, экономика, сообщение, доказательство, проверка |
| Продолжение | Верно ли восстановлены этап, следующий шаг и устаревшие основания |

Оценку содержательности желательно проводить человеку, который не знает режим.
Не подменять полный расход временем локального скрипта. Результаты корпуса
вымышленных задач не являются доказательством коммерческой эффективности.

## Одинаковый запрос не всегда означает сравнение версий

Два продолжения одной текущей версии с разной историей — `behavioral_repeat`.
Для `version_comparison` нужны разные ревизии агента и свежие контексты.
Для `agent_vs_chat` один режим — папка агента, второй — обычный чат без неё.
Назначение ролей и доступные инструменты фиксируются заранее. Не переносите
ответ из первого режима во второй и не подсказывайте ожидаемую рекомендацию.

Создайте отдельную папку на каждый запуск с исходным запросом, материалами,
сырым ответом и манифестом по `templates/benchmark-run.json`. Заполните реальные
значения; неизвестные настройки не выдавайте за контролируемые. Проверка:

```text
python scripts/compare_runs.py run-a/run.json run-b/run.json --kind version_comparison
```

Скрипт читает реальные файлы и сравнивает хеши запроса/материалов, модель,
настройки, инструменты, лимит, контекст и заявленную ревизию. Он не измеряет
истинность метаданных, качество ответа или победителя. Один успешный запуск
недостаточен. Используйте не менее трёх повторов каждого режима с одинаковой
задачей, отдельного оценщика и заранее заданную рубрику. Размер повторов —
практический минимум для диагностики, не гарантия статистической мощности.

Раздельно фиксируйте ошибки источников/чисел, подмену гипотез фактами,
содержательность альтернатив, согласованность стратегий и выполнимость плана.
Факт улучшения нельзя получать из количества файлов, тестов Python, длины
ответа, самопроверки агента или времени между записями журнала.
