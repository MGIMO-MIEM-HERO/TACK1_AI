# Разбор пользовательского пути

1. Уточни пользователя и задачу, версии экранов, устройство и ширину. Попроси только недостающие материалы, без которых нельзя оценить путь.
2. Для каждого шага запиши вход, действие, наблюдаемый результат и следующий шаг. Ссылайся на конкретный экран/элемент; не приписывай скрытые функции.
3. Отдели наблюдаемый дефект от гипотезы: «кнопки нет на скриншоте» — наблюдение; «пользователь не понимает» — гипотеза до проверки.
4. Проверь успех, ошибку, пустое состояние, задержку, повторную отправку, возврат и телефон. Не объявляй аудит WCAG без соответствующей проверки.
5. Предложи минимальное исправление, сильное возражение и проверку с пользователем. Добавь сведения в журнал evidence.
6. При отсутствии скриншотов или доступа разбирай только предоставленный код/описание. Не называй это наблюдением реального поведения.
