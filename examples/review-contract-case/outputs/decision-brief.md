# Проверить понятность статусов без разработки

Статус: validation. Выбор человека: не зафиксирован.

## Цель
Предложить ограниченную проверку; не выдавать план за результат

## Рекомендация
Предлагается O1: подготовить бумажную проверку, потому что разработка ограничена E1, а польза проверки остаётся гипотезой E2. Если добровольцы недоступны, ограничиться материалами и не заявлять проверенный спрос.

## Ограничения
- Учебный кейс
- Бюджет 0 — не стоимость работы модели
- Три дня
- Разработчик недоступен
- Спрос неизвестен

## Решение человека
Выбор: ожидается; владелец: не назначен

## Альтернативы
### O0: Оставить текущую версию
Польза: Нет новых работ
Затраты и риски: Понятность останется неизвестной
Возражение: Малую проверку можно подготовить без кода
Основания: E1
### O1: Подготовить бумажный сценарий и протокол
Польза: Проверка понимания доступна без разработчика
Затраты и риски: Нет подтверждённого доступа к людям; не проверяет реальную обработку
Возражение: Ручная помощь может скрыть недостатки сценария
Основания: E2
### O2: Заморозить расширение
Польза: Сохранить время команды
Затраты и риски: Не получим новых сведений
Возражение: Отсутствие данных не доказывает отсутствие потребности
Основания: E1
### O3: Разработать интерактивный путь
Польза: Можно показать реальный интерфейс
Затраты и риски: Сейчас недоступен разработчик
Возражение: Не соответствует текущим ресурсам
Основания: E1

## Продуктовая стратегия
- **Аудитория**: Доброволец, пытающийся понять состояние учебной заявки
- **Задача**: Назвать статус и следующий шаг без подсказки
- **Альтернативы**: Текущая версия, бумажная проверка, разработка позже, заморозка
- **Направление**: Подготовка ограниченной проверки понимания
- **Осознанные отказы**: Не автоматизировать официальные документы и не обещать улучшение времени обработки
- **Экономика**: Ноль планируемых денежных покупок; часы команды и стоимость модели неизвестны

## Коммуникационная стратегия
- **Аудитория**: Потенциальные добровольцы; их наличие не подтверждено
- **Ситуация**: После попытки пройти учебный сценарий
- **Барьер**: Непонятный результат отправки
- **Сообщение**: Помогите проверить понятность учебного сценария
- **Подтверждение обещания**: Показать сценарий без обещания готового сервиса
- **Каналы**: Приглашение только после решения владельца; агент ничего не отправляет

## План проверки
- **Гипотеза**: Понятны ли статусы без объяснений ведущего
- **Основная метрика**: Число попыток с верным пониманием / число завершённых попыток; пока неизвестно
- **Сравнение**: Два варианта формулировок с одинаковым заданием и чередованием порядка
- **Окно наблюдения**: План на три дня, начало не назначено
- **Защитные показатели**: Вымышленные данные, добровольность, запрет подсказок в исходном ответе
- **Правило решения**: Критическая ошибка требует переработки; переход к разработке решает человек
