# Аудит маркетинговых обещаний

Отдельный сохраняемый результат связывает обещание с возможностями продукта,
доказательствами и осторожной формулировкой. Статусы: подтверждено, частично
подтверждено, не подтверждено, противоречит данным. Отсутствие измерения не
доказывает ложность, а перефразирование не заменяет доказательство.

## Запуск

Агент сначала заполняет `product_capabilities` и `marketing_claims` по
[`workflows/marketing-claims-audit.md`](../workflows/marketing-claims-audit.md).
Поля необязательны для старых кейсов, но зарегистрированные обещания требуют
аудита перед итоговой запиской.

```sh
python scripts/claims_audit.py prepare projects/my-case/project.json --review-id R1 --out projects/my-case/claims-R1.json
# LLM читает источники, заполняет все assessments и проверяет смысл выводов.
python scripts/claims_audit.py record projects/my-case/project.json --review projects/my-case/claims-R1.json
python scripts/claims_audit.py inspect projects/my-case/project.json
python scripts/claims_audit.py report projects/my-case/project.json --out projects/my-case/claims-R1.md
```

Схемы находятся в `schemas/project.schema.json`: productCapability, marketingClaim,
marketingClaimsAudit. Валидатор на стандартной библиотеке дополнительно проверяет
ID, покрытие каждого обещания, исходный текст и связь с возможностями.
CLI не вызывает модель и не сочиняет оценки. `prepare` создаёт незавершённый
шаблон; незаполненный шаблон сохранить нельзя. Для следующей версии нужен новый ID.

## Проверки и сохранение

- Происхождение фактических утверждений, точные сохранённые фрагменты, статусы
  доказательств и доступность/срок источников проверяются общим `quality.support_blockers`.
  Прежний стресс-разбор использует ту же функцию без копии правил.
- Для полной поддержки возможности нужны зарегистрированные наблюдения реализации.
  Синтетика, модельный ответ или описание планов их не заменяют.
- Для количественного обещания нужны измерения `measured_fact` в подходящей области.
  Для причинного эффекта — также завершённый real/causal_effect-дизайн, результаты
  и относящиеся к нему основания. Одной декларации «исследование выполнено» мало.
- Совпадение формата не доказывает смысловую применимость. `coverage` и scope_match
  фиксируют результат содержательной работы LLM; их достоверность оценивает человек.
- В `marketing_claims_audits` дописываются версии с baseline, автором, ограничениями
  и фактической датой записи. Baseline хранит каталог координат и источников для
  исторического самостоятельного отчёта. Старые версии не объявляются актуальными.
- Запись аудита не меняет сообщение. Если оно всё ещё содержит зарегистрированное
  неподтверждённое обещание, публикационный блокер запрещает `report --final`.
  Сохранить сам честный диагноз при этом можно. Черновик показывает проблему.
- Изменение сообщения, возможностей, ограничений или источников делает аудит stale.
  Хеш включает значимый контекст и содержимое источников. Служебные версии двух
  видов аудита не инвалидируют друг друга; реальные изменения данных инвалидируют.
  Общая самопроверка стратегии после записи всё равно требует обновления.
- Механизм атомарной записи и дописывания журнала общий со стресс-разбором.
  При частичном успехе команда явно сообщает: сначала прочитайте состояние,
  не повторяйте запись вслепую. Стоимость и время без измерений остаются неизвестны.

## Учебная демонстрация

```sh
python scripts/claims_audit.py inspect examples/marketing-claims-case/project.json
python scripts/verify_claims_demo.py
```

В авторском вымышленном брифе помощник только планируется, измерений нет.
«Сократить время подготовки вдвое» получает статус «не подтверждено», а не «ложь».
Предлагаемый текст: «Планируем помощника для составления плана подготовки.
Влияние на время ещё не измерено». Исходное обещание остаётся в истории аудита.

Проверка во временной копии воспроизводит неподтверждённое сообщение, устаревание,
запрет итогового экспорта, ЯВНОЕ применение безопасного текста, новую версию
аудита и успешный экспорт. История и исходник сохраняются, эксперименты не
объявляются выполненными, выбор за человека не записывается. Это проверка
инструмента, не LLM benchmark или настоящий эксперимент об ускорении подготовки.

## Ограничения

Нет исчерпывающего автоматического поиска всех обещаний в произвольном тексте,
распознавания перефразировок и доказательства того, что цитата влечёт утверждение.
Проверка совпадения с текущим сообщением ловит зарегистрированный исходный текст;
другие формулировки должен найти и оценить агент. Числовые маркеры — ограниченная
эвристика, не понимание языка. Предлагаемый текст требует содержательной проверки.
Это не юридическое заключение. Дополнительных сервисов и зависимостей нет.
