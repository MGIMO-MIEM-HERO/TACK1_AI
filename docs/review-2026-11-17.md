# Проверка состояния агента

Проверенная основная версия: `8135c11` (PR №1 принят). Ветка
`feature/agent-v2` (`3752e93`) пока отдельная: её 13 тестов проходят локально,
но это не означает совместимость при слиянии с main. Автоматического слияния
не выполнялось. При объединении нужно согласовать checkpoint, валидатор,
схему состояния, инструкции и два журнала расходов (`runs.jsonl`/`ledger.jsonl`).

## Исправления основной версии

- Экспорт отказывается перезаписывать состояние проекта, зарегистрированные
  источники, снимки источников и журнал расходов.
- Все три команды чтения состояния поддерживают UTF-8 с BOM (Windows).
- Валидатор отклоняет неверные типы рекомендации, снимка, признака синтетики,
  координат доказательства и списков вопросов до выполнения рабочих команд.
  Неизвестная база путей больше не подменяется молча базой репозитория.
- Чтение CSV/TSV сохраняет переносы строк внутри ячеек в кавычках.
- Строгий аудит требует текстового обоснования рекомендации.
- Добавлены автоматические проверки GitHub для Windows/Linux и Python 3.10/3.14.

Локально на Python 3.14: 9 тестов основной версии, проверка сквозного демо
с изменением/восстановлением/удалением источника, строгий аудит campus-strategy
и валидация activation-case прошли. Проверки других ОС/версий выполняются CI.

## Что проверить владельцу ИИ-направления

1. Открыть корень репозитория в Codex, прочитать `AGENTS.md`, продолжить
   `examples/campus-strategy/project.json` через `checkpoint.py … resume`.
2. Попросить объяснить альтернативы, факты, гипотезы и неизвестное.
3. Добавить ограничение бюджета/срока и проверить пересмотр стратегии.
4. Открыть новый чат и проверить восстановление ограничений из файлов.
5. Записать фактический прогон и расходы; подготовить обязательное конкурсное
   видео и сравнение с обычным чатом по `docs/benchmark-plan.md`.

Эта проверка инструментов не является оценкой качества LLM, живым интервью
или подтверждением соответствия дополнительному официальному демо-брифу.


## Объединение с agent-v2

По запросу владельца обе ветки объединены. Сохранены инструменты snapshot,
ledger, Claude/Cursor, аудит и кейс campus-strategy. Схема и шаблон объединены;
варианты campus-strategy получили kind, соответствующий их прежнему смыслу.
Новые расходы пишутся в ledger, runs остаётся архивом.

Причины падений CI: сырые SHA текстовых источников зависели от LF/CRLF;
Windows временные пути имели короткую/полную форму. fingerprint теперь
нормализует окончания строк известных текстовых форматов и разрешает базовый
путь. Контрольная точка campus обновлена после проверки неизменности текста.
Добавлены два регрессионных теста, матрица больше не отменяет остальные ОС
после первого сбоя. Для процессов Python в CI включён UTF-8.
